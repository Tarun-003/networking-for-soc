# 🌐 DNS & HTTP for SOC Analysts

Understanding DNS and HTTP is essential to analyze web traffic and detect attacks.

---

## 🔍 What is DNS?

DNS (Domain Name System) translates domain names into IP addresses.

Example:
google.com → 142.250.x.x

---

## 🔄 How DNS Works

1. User enters a website (example.com)
2. DNS query is sent
3. DNS server returns IP address
4. Browser connects to the server

---

## 📡 DNS Uses

- Domain resolution
- Web access
- Email services

---

## 🚨 DNS in SOC

Suspicious signs:
- Requests to unknown domains
- Random or long domain names
- Frequent DNS queries

Example:
abc123-malware-domain.xyz → suspicious

---

## 🌍 What is HTTP?

HTTP (HyperText Transfer Protocol) is used for communication between browser and web server.

---

## 🔒 What is HTTPS?

HTTPS = Secure version of HTTP

- Uses encryption (SSL/TLS)
- Protects data from attackers

---

## 🔄 How HTTP Works

1. Client sends request
2. Server responds with data
3. Browser displays webpage

---

## 📊 Common HTTP Methods

| Method | Purpose |
|--------|--------|
| GET | Retrieve data |
| POST | Send data |
| PUT | Update data |
| DELETE | Remove data |

---

## 🚨 HTTP in SOC

Suspicious signs:
- Unusual URLs
- Data sent to unknown servers
- Large POST requests
- Access to malicious websites

---

## 📌 Example

User clicks phishing link  
→ DNS resolves fake domain  
→ HTTP request sent  
→ Attacker steals data

---

## ✅ Summary

DNS resolves domain names, and HTTP enables web communication.  
Both are critical for detecting phishing and web-based attacks in SOC.
